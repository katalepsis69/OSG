# BTA OSG Document Status Tracking & Monitoring System  
## Path A: Full Production Modular Implementation Plan  
### Version 2.1
---
## 1. Purpose
This document defines the full production-grade implementation plan for the **BTA OSG Document Status Tracking & Monitoring System**.
Path A is intended for official deployment and long-term use by the Office of the Secretary-General.
It provides:
```text
Full VB.NET WinForms implementation
SQL Server production database
Role-Based Access Control
RFID authentication
SG directive tracking
Routing history
Storage landmark tracking
Google Drive PDF access
Append-only audit trail
Automated self-test mode
Deployment and UAT readiness
```
Path A is the recommended path if the system is intended for real production use.

## 3. Scope of Path A
### 3.1 In Scope
Path A shall support:
1. RFID-based user sign-in.
2. Role-based access control.
3. Document registration.
4. Automatic document coding.
5. Secretary-General directive recording.
6. Routing and assignment history.
7. Physical storage landmark tracking.
8. Google Drive PDF soft-copy launching.
9. Search and filtering.
10. Audit trail.
11. SQL Server production storage.
12. Local test mode.
13. Automated self-test.
14. Basic administrative management of users, cards, roles, and reference data.
---
### 3.2 Out of Scope Unless Approved Later
The following are not included unless explicitly approved:
- Full document imaging/scanning module
- Full electronic signature
- Workflow automation beyond SG directives
- Mobile application
- Public web portal
- Email notifications
- SMS notifications
- Blockchain audit storage
- Automatic Google Drive upload
- Google Drive permission management
- OCR or full-text indexing of scanned documents
---
## 4. Production Architecture
Path A shall use a modular architecture.
```text
UI
 ↓
Services / Business Rules
 ↓
Repositories / Data Access
 ↓
SQL Server
```
The UI must not directly execute SQL queries.
All business rules shall be enforced in the service layer.
All data access shall be performed through repositories.

## 6. Database Strategy
### 6.1 Production Database
Production shall use SQL Server.
Recommended database name:
```text
BTA_OSG_DB
```
Recommended SQL Server edition:
```text
SQL Server Standard/Enterprise, or
SQL Server Express if data volume and concurrency are within Express limits
```
---
### 6.2 Development Database
Development shall preferably use:
```text
SQL Server Express LocalDB
```
This gives the closest compatibility with production SQL Server.
---
### 6.3 Connection Approach
Recommended development connection:
```text
Server=(localdb)\MSSQLLocalDB;Database=BTA_OSG_DB;Integrated Security=true;Encrypt=true;TrustServerCertificate=true;
```
Recommended production connection:
```text
Server=OSG-SQL-01;Database=BTA_OSG_DB;Integrated Security=true;Encrypt=true;TrustServerCertificate=false;
```
SQL authentication should only be used if Windows Authentication is not possible.
If SQL authentication is used:
```text
Do not store password in source code.
Use protected configuration.
Restrict access to configuration files.
Use strong passwords.
```

## 9. Data Visibility Rule
For document queries:
```text
IF user has DOCUMENT_VIEW_ALL
    return filtered documents according to search criteria
ELSE
    return only documents assigned to:
        - the user directly, or
        - one of the user's roles, or
        - the user's office
```
Administrative Staff shall not see all documents by default.

### 10.4 Document Auto-Coding Module
Code format:
```text
PREFIX-yyyy-###
```
Examples:
```text
RES-2026-001
BLL-2026-001
REP-2026-001
```
Concurrency-safe method:
```text
1. Begin transaction
2. Lock sequence row for DocumentTypeCode + SequenceYear
3. Insert sequence row if missing
4. Increment LastNumber
5. Generate DocCode
6. Insert document
7. Commit transaction
8. Retry on unique constraint violation
```
Do not generate code by counting rows.
---
